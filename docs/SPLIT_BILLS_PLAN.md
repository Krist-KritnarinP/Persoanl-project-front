# แผนฟีเจอร์หารบิลทริป — ไม่มี AI

สถานะ: **แผนรอพัฒนา ยังไม่เริ่ม implementation** • 2026-09-28
คำสั่งล่าสุด: ฟีเจอร์พื้นฐานใช้งานยืดหยุ่น ใส่ VAT / service charge / tips และเคลียร์ยอดบางคนระหว่างทริปได้

## 1. ประสบการณ์ที่ต้องได้

หน้า Trip เพิ่มแท็บ “ค่าใช้จ่าย / หารบิล” มี 3 ส่วน:
- บิลทั้งหมด: วันที่ ชื่อบิล ยอด ผู้จ่าย คนหาร กรองคน/วันที่/กิจกรรม/สถานะได้
- ยอดรายคน: ออกเงินไปเท่าไร ส่วนที่ต้องรับผิดชอบ คืน/รับคืนแล้วเท่าไร และยังค้างเท่าไร
- การคืนเงิน: ประวัติผู้โอน → ผู้รับ จำนวน วันเวลา และบิลที่เคลียร์

Flow: เพิ่มสมาชิก → เพิ่มบิล → เลือกผู้จ่ายและคนหาร → ตรวจยอดแยกรายคน → บันทึก → คืนเงินได้ทันทีระหว่างทริป
ทุกหน้ารองรับ th/en/zh/ko และมือถือ ใช้รูปแบบ UI เดิม ไม่เพิ่ม AI หรือเรียก provider

## 2. สมาชิกและวิธีหาร

- เพิ่มสมาชิกด้วยชื่อได้ก่อน ไม่บังคับทุกคนสมัครบัญชี; สมาชิกมี ID คงที่ ไม่ใช้ชื่อเป็น primary key
- MVP ให้เจ้าของทริปจัดการรายการแทนกลุ่มก่อน; ชื่อสมาชิกเฉย ๆ ไม่ได้สิทธิ์เข้าอ่านข้อมูล
- เลือกคนที่ร่วมแต่ละบิลได้ ไม่ต้องหารทั้งทริปเสมอ
- หารเท่ากัน / กำหนดจำนวนเงิน / เปอร์เซ็นต์ / จำนวนส่วน (เช่น 2:1:1)
- บิลหนึ่งมีผู้จ่ายได้หลายคน; ยอดที่แต่ละคนจ่ายรวมกันต้องเท่ากับยอดบิล
- เพิ่มรายการย่อยได้ เช่น คนหนึ่งไม่กินเครื่องดื่ม ให้เลือกร่วมเฉพาะรายการที่กิน
- โหมดธรรมดากรอกยอดเดียวได้ ไม่บังคับแตกทุกรายการ; โหมดละเอียดค่อยเพิ่มรายการย่อย
- ซ่อน/หยุดใช้สมาชิกที่ออกจากทริปได้ แต่ห้ามลบ ID ที่มีประวัติเงิน

## 3. VAT / service charge / tips

ทุกช่อง optional เริ่มต้นปิด ไม่มีการบังคับอัตราตามประเทศ:
- service charge: จำนวนเงินหรือ %; ถ้าเป็น % ใช้ยอดรายการก่อน VAT/ทิปเป็นฐาน
- VAT: จำนวนเงินหรือ % และเลือก “บวกเพิ่ม” หรือ “รวมในยอดแล้ว”
- VAT แบบ % เลือกฐานได้: เฉพาะรายการ หรือรายการ + service charge
- ทิป: จำนวนเงินหรือ %; เลือกฐาน % เป็นก่อนหรือหลัง VAT/service charge และแสดงฐานตัวเลขให้เห็น
- รองรับ “รวม service charge ในยอดแล้ว” ด้วยช่องยอดที่รวมอยู่ (จำนวนเงิน); ไม่บวกซ้ำ ไม่ตีความ % รวมย้อนกลับแบบเดา
- ถ้ามี VAT รวมอยู่: แสดงส่วนภาษาที่แยกออกจากฐานที่เลือก ไม่เพิ่มยอดจ่ายซ้ำ; แสดงข้อผิดพลาดเมื่อระบุฐาน/ยอดรวมขัดกัน
- เลือกหารแต่ละส่วนเพิ่มแยกกันได้: ตามสัดส่วนอาหาร / เท่ากันเฉพาะคนที่เลือก / ระบุยอดรายคน
- เช่น คน A ออกทิปเองทั้งหมดได้ โดยไม่ได้เปลี่ยนส่วนอาหารของคนอื่น
- VAT/service/tip ที่แยกจากยอดรวมอยู่แล้ว เป็นส่วนของยอดตั้งต้น ต้องหักออกก่อนแบ่งส่วนรายการ ห้ามแจกซ้ำสองรอบ
- Preview แสดง รายการ + service ที่บวกเพิ่ม + VAT ที่บวกเพิ่ม + ทิปที่บวกเพิ่ม = ยอดสุทธิ พร้อมรายคนและเศษปัด
- มีช่อง “ยอดสุทธิตรงใบเสร็จ” สำหรับตรวจเทียบ; หากไม่ตรงต้องแก้หรือใส่รายการปรับเศษอย่างชัดเจน ห้ามระบบเปลี่ยนราคาเงียบ ๆ
- ค่าลบไม่ใช้แทนการคืนเงิน; คืนเงิน/ยกเลิกบิลต้องเป็นรายการอ้างอิงแยก

ตัวอย่างตรวจสูตร (ตัวเลขสมมติสำหรับทดสอบ ไม่ใช่คำแนะนำภาษี):
- รายการ 1,000 + service 10% = 100; VAT 7% ของ 1,100 = 77; ทิป 50 → รวม 1,227
- A/B หารรายการ+service+VAT เท่ากัน = 588.50 ต่อคน; A รับผิดชอบทิป50 → A638.50 / B588.50
- A จ่ายเต็ม1,227 → B ค้าง A588.50; B คืน200 → เหลือ388.50; ยอดค่าเที่ยวคง1,227
- ยอด1,070 ที่รวม VAT7% แล้ว (ไม่มีส่วนอื่น): ฐาน1,000 ภาษี70 รวมยัง1,070

## 4. เคลียร์บางคน / บางบิลระหว่างทริป

หน้ารายคนมี “คืนเงิน” เลือกผู้รับ แล้วเลือกขอบเขต:
1. เลือกบิลที่ต้องการเคลียร์กับผู้รับคนนั้น และคืนเต็มหรือบางส่วน
2. เคลียร์ยอดสุทธิระหว่างสองคนถึงตอนนี้ โดย preview ว่าครอบคลุมบิลใดและจัดสรรคืนเท่าไร

กติกาที่ลดความงง:
- เคลียร์ A/B ได้โดยไม่ปิดบิลของ C และไม่ต้องจบทริปก่อน
- ชำระเพียงบางส่วนได้ แสดงยอดก่อนคืน / คืนครั้งนี้ / คงเหลือ
- บิลหลายผู้จ่ายต้องแสดงเจ้าหนี้และส่วนที่จัดสรรให้ชัดเจนก่อนยืนยัน
- ยืนยันรายการคืนผูกกับ bill/share allocations จริง บันทึก transaction เดียวกับยอด; ห้ามเก็บแค่ flag paid
- หน้าจอแยก “ฉันติดหนี้” กับ “คนอื่นติดฉัน”; net=0 อย่างเดียวไม่ได้แปลว่าทุกคู่คืนครบ
- เมื่อออกจากทริปก่อน เคลียร์ได้เฉพาะบิลที่บันทึกอยู่ ณ ตอนนั้น; บิลเพิ่มทีหลังอาจทำให้มียอดใหม่
- “เคลียร์แล้วถึงวันที่/เวลา…” พร้อมยอดใหม่ภายหลัง ไม่สื่อว่าปิดบัญชีตลอดไป
- ห้ามคืนเกินยอดคงเหลือของคู่/บิลที่เลือกใน MVP; เงินล่วงหน้าแยกไว้พัฒนาภายหลัง
- ต้องยืนยันก่อนบันทึก และป้องกันกดซ้ำ; ยกเลิกการคืนด้วย reversal มีประวัติ ไม่ลบทิ้งเงียบ ๆ
- MVP เป็น “บันทึกคืนเงินโดยเจ้าของทริป” ไม่ใช่ตรวจสอบธนาคารหรือผู้รับยืนยันแล้ว
- ยังไม่ทำ simplify debts ข้ามคู่โดยอัตโนมัติ เพื่อรักษาความเชื่อมโยงบิล; อนาคตเพิ่มเป็นตัวเลือกพร้อมอธิบายการย้ายหนี้

กรณี acceptance สำคัญ: บิล900 Aจ่าย คนA/B/Cหารเท่ากัน → BคืนA300 → Bคงเหลือ0, Cยังค้างA300; บิลใหม่120 Aจ่าย A/Bหาร → Bมียอดใหม่60 โดยการคืน300เดิมยังอยู่

## 5. แยกจากงบประมาณและ Dashboard ปัจจุบัน

- Activity.price เดิมยังเป็นราคาที่บันทึก/ประมาณการ ไม่สร้างหนี้ให้สมาชิกอัตโนมัติ
- “สร้างบิลจากกิจกรรม” นำชื่อ/วันที่/ราคาเป็นค่าตั้งต้น ผู้ใช้ตรวจและยืนยันก่อนเป็นบิลจริง
- บิลผูก activityId แบบ optional; ค่าแท็กซี่/ซื้อของที่ไม่มีในแผนเพิ่มได้เอง
- Dashboard แยก “งบ/ราคากิจกรรม” และ “ยอดบิลที่ยืนยัน” ห้ามนำสองแหล่งมาบวกซ้ำ
- การคืนเงินระหว่างสมาชิกไม่ใช่ค่าใช้จ่ายใหม่ ไม่เพิ่มยอดเที่ยว
- MVP ใช้ THB สกุลเดียวต่อทริปให้ตรงระบบเดิม เก็บ currency ชัดเจน; การเปลี่ยนสกุลหลังมีบิลต้องไม่ทำได้เงียบ ๆ
- หลายสกุลเงิน/แปลงค่าเงินเป็นงานต่อยอด ไม่เอาเลขต่างสกุลมารวมตรง ๆ

## 6. แนวทางข้อมูลและความถูกต้อง

ชื่อด้านล่างเป็นแบบร่าง ต้องทบทวน schema เดิมก่อน migration:
- TripMember: trip, ชื่อ, optional user link, active/archived
- Expense: trip, optional activity, วันที่, ชื่อ, currency, draft/posted/void, version
- ExpenseLine / Charge: ยอดรายการ ฐานคำนวณ VAT/service/tip โหมดรวม/บวกเพิ่ม สูตรและยอดที่ยืนยัน
- ExpensePayment: member + จำนวนที่ออกก่อน
- ExpenseShare: member + ส่วนที่รับผิดชอบ รวมส่วนแบ่งรายการ/ค่าเพิ่ม
- Settlement + Allocation: จากใครถึงใคร จำนวน วันที่ อ้างบิล/ส่วนหนี้ที่คืน และ reversal
- บันทึกผู้กระทำ/เวลา/version ก่อนและหลังเมื่อแก้การเงิน; เก็บหลักฐานการคำนวณเพื่อตรวจย้อนหลัง

กติกา implementation:
- คำนวณเงินหน่วยย่อยเป็น integer; % ใช้ค่าทศนิยมแน่นอน ไม่ปล่อย floating point drift
- ปัดแต่ละ charge ที่ระดับบิล จากนั้นแจกเศษรายคนแบบ deterministic ตามเศษมากก่อนและ member ID เมื่อเท่ากัน
- ผลรวม payments = bill total = shares; allocations ต้องไม่เกินหนี้คงเหลือ
- Server คำนวณ/ตรวจใหม่เสมอ ไม่เชื่อยอดรวมจาก Front
- บันทึกบิล/ส่วนแบ่ง/คืนเงินเป็น transaction; idempotency และ version check กันซ้ำ/แก้พร้อมกัน
- ทุก ID (trip/member/activity/expense/settlement) ต้องอยู่ในทริปเจ้าของที่ได้รับอนุญาต ห้ามเชื่อ userId จาก request
- กรณีมี settlement แล้ว ล็อกแก้ยอด/ผู้จ่าย/ส่วนแบ่งของบิลนั้นใน MVP; ต้อง reversal การคืนที่เกี่ยวข้องก่อนจึงแก้แบบมี version history ได้
- ยังแก้ชื่อ/หมายเหตุที่ไม่เปลี่ยนยอดได้โดยมี log; draft แก้ได้ตามปกติ
- ลิงก์แชร์แผนเที่ยวเดิมไม่เปิดเผยบิล/หนี้/ชื่อสมาชิกเพิ่มโดยอัตโนมัติ
